# Планировщик задач

Веб-приложение на Go для управления задачами с хранением данных в SQLite.
Фронтенд предоставлен Яндекс Практикумом.

## Возможности

- Создание, просмотр, редактирование и удаление задач.
- Список задач с сортировкой по возрастанию даты.
- Поиск по заголовку, комментарию и конкретной дате.
- Повторение задач через заданное количество дней, ежегодно,
  по дням недели и дням месяца.
- При выполнении одноразовая задача удаляется, а периодическая
  переносится на следующую дату.
- Необязательный вход по паролю с использованием JWT.

## Выполненные задания со звёздочкой

- Настройка порта через `TODO_PORT`.
- Настройка пути базы данных через `TODO_DBFILE`.
- Правила повторения `w` и `m`.
- Поиск задач по тексту и дате.
- Аутентификация через `TODO_PASSWORD` и JWT.
- Сборка Docker-образа и запуск контейнера с базой данных на хосте.

## Локальный запуск

Требуется Go версии 1.27 или новее. Команды ниже приведены для PowerShell.

Из корня проекта выполните:

```powershell
go mod download
go run .
```

Откройте http://localhost:7540/.

При первом запуске приложение создаёт файл `scheduler.db`
с таблицей задач и индексом по дате. При последующих запусках
использует существующую базу.

Порт 7540 должен быть свободен. Для остановки сервера нажмите `Ctrl+C`.

### Переменные окружения

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `TODO_PORT` | Порт сервера | `7540` |
| `TODO_DBFILE` | Путь к файлу SQLite | `scheduler.db` в текущей папке |
| `TODO_PASSWORD` | Пароль для входа | Вход без пароля |

Родительская папка для файла базы должна существовать.

Пример запуска с настройками:

```powershell
$env:TODO_PORT = '7541'
$env:TODO_DBFILE = Join-Path (Get-Location).Path 'scheduler.db'
$env:TODO_PASSWORD = 'test-password'
go run .
```

В этом примере приложение доступно по адресу http://localhost:7541/.
`test-password` — учебный пример пароля.

### Аутентификация

Если `TODO_PASSWORD` не задана или пустая, API работает без входа.
Если пароль задан, фронтенд перенаправляет пользователя на `/login.html`.

После успешного входа выдаётся JWT сроком на 8 часов.
Фронтенд сохраняет его в cookie `token`.
После истечения срока, перезапуска сервера или смены пароля
требуется войти повторно.

Переменные окружения PowerShell действуют в текущем терминале.
Файл `.env` автоматически не загружается.

## Запуск тестов

Тесты обращаются к работающему серверу и напрямую к его базе SQLite.
Сначала запустите локальный сервер через `go run .`,
затем запускайте тесты во втором терминале из корня проекта.

В `tests/settings.go` используются настройки:

```go
var Port = 7540
var DBFile = "../scheduler.db"
var FullNextDate = true
var Search = true
var Token = os.Getenv("TODO_TOKEN")
```

Для чтения `TODO_TOKEN` в этом файле импортирован пакет `os`.

Если сервер использует нестандартный порт или путь базы,
задайте во втором терминале соответствующие `TODO_PORT` и `TODO_DBFILE`.
Для `TODO_DBFILE` удобно использовать абсолютный путь:
сервер и тесты должны обращаться к одной базе.

**Внимание:** тесты изменяют данные и удаляют текущие задачи
из проверяемой таблицы `scheduler`.

### Без аутентификации

Сервер должен быть запущен без `TODO_PASSWORD`.
Во втором терминале выполните:

```powershell
Remove-Item Env:TODO_TOKEN -ErrorAction SilentlyContinue
go test -count=1 ./tests
```

### С аутентификацией

Если сервер запущен на порту 7540 с учебным паролем `test-password`,
получите токен во втором терминале:

```powershell
$signinBody = @{ password = 'test-password' } | ConvertTo-Json
$signinResponse = Invoke-RestMethod -Method Post -Uri 'http://localhost:7540/api/signin' -ContentType 'application/json' -Body $signinBody
$env:TODO_TOKEN = $signinResponse.token
go test -count=1 ./tests
```

Если выбран другой порт или пароль, измените адрес запроса
и значение `password` соответственно.

После перезапуска сервера получите новый токен.
Значение токена не записывается в файлы проекта.

## Запуск через Docker

Требуется Docker с поддержкой Linux-контейнеров.
На Windows запустите Docker Desktop и дождитесь готовности Engine.

### Сборка образа

Из корня проекта выполните:

```powershell
docker build -t todo-app:v1 .
```

### Запуск контейнера

Остановите локальный сервер через `Ctrl+C`, если он занимает порт 7540.

```powershell
$dataPath = Join-Path (Get-Location).Path 'data'
New-Item -ItemType Directory -Path $dataPath -Force | Out-Null

docker run -d --name todo-app -p 127.0.0.1:7540:7540 --mount "type=bind,source=$dataPath,target=/data" todo-app:v1
```

Откройте http://localhost:7540/.

Внутри контейнера используются настройки:

- `TODO_PORT=7540`;
- `TODO_DBFILE=/data/scheduler.db`.

Папка `data` на компьютере подключается к `/data` контейнера.
Поэтому база находится в `data/scheduler.db` и сохраняется
после удаления контейнера. Это отдельная база:
локальный файл `scheduler.db` из корня проекта не используется.

### Управление контейнером

Просмотр журналов:

```powershell
docker logs todo-app
```

Остановка и удаление контейнера:

```powershell
docker stop todo-app
docker rm todo-app
```

Для повторного создания выполните команду `docker run` из раздела выше.
Папку `data` сохраняйте, если нужны ранее созданные задачи.

### Запуск с паролем

Если контейнер `todo-app` уже существует, сначала остановите
и удалите его командами выше.

Из корня проекта выполните:

```powershell
$dataPath = Join-Path (Get-Location).Path 'data'
New-Item -ItemType Directory -Path $dataPath -Force | Out-Null
$env:TODO_PASSWORD = 'test-password'

docker run -d --name todo-app -p 127.0.0.1:7540:7540 --mount "type=bind,source=$dataPath,target=/data" -e TODO_PASSWORD todo-app:v1
```

`test-password` — учебный пример. Параметр `-e TODO_PASSWORD`
передаёт значение переменной из текущего терминала в контейнер.
